# IT Asset, Phone Directory & Dashboard System — v3 (Admin / Dynamic Schema)

ระบบจัดการอุปกรณ์ IT และสมุดโทรศัพท์ภายใน สำหรับทีม IT Support โรงพยาบาล (ใช้งานคนเดียว, หลายสาขา)
Frontend: HTML + CSS ล้วน (ไม่มี framework) + Vanilla JS บน GitHub Pages
Backend: Google Apps Script + Google Sheets

## สิ่งที่ต่างจาก v2

- **ไม่มีอะไร hardcode ในโค้ดอีกแล้ว** — สาขา, PIN, user/password login, ประเภทอุปกรณ์, ฟิลด์ของแต่ละประเภท
  ทั้งหมดย้ายไปเก็บในชีต แก้ไขได้จากหน้าเว็บ (แท็บ **Admin**) ไม่ต้องแตะโค้ดอีกต่อไป
- **login ตรวจฝั่ง server** — user/password ไม่ฝังอยู่ใน `app.js` ที่เปิด source ดูได้อีกแล้ว (ปลอดภัยขึ้นกว่า v2)
- **เพิ่ม/ลบฟิลด์และประเภทอุปกรณ์แบบจริง** ผ่านหน้า Admin — backend ใช้คำสั่ง `insertColumnBefore`/`deleteColumn`/`insertSheet`/`deleteSheet`
  ของ Apps Script แทรก/ลบคอลัมน์-ชีตจริง ข้อมูลแถวอื่นไม่เลื่อนตำแหน่งผิด
- **ฟิลด์มี 3 ชนิด**: ข้อความ (text) / ตัวเลือก (dropdown, กำหนดตัวเลือกเอง) / วันที่ (date)
- **ดู Log ย้อนหลังในเว็บได้** กรองตามช่วงวันที่และประเภทอุปกรณ์

## ขั้นตอนติดตั้ง / ย้ายจาก v2

### ถ้าเป็นการติดตั้งใหม่ทั้งหมด (ยังไม่เคยมีข้อมูล)

1. สร้าง Google Sheet ใหม่ 1 ไฟล์ > Extensions > Apps Script > วาง `Code.gs` ทับ > Save
2. เลือกฟังก์ชัน `setupSheets` จาก dropdown > Run (ครั้งแรกจะมี popup ขอสิทธิ์ ให้ Allow)
   จะได้ชีตครบ: `Config`, `SchemaTypes`, `SchemaFields`, `Log`, และชีตอุปกรณ์ 5 ประเภทเริ่มต้น
3. Deploy > New deployment > Web app > Execute as: Me, Who has access: Anyone > Deploy > คัดลอก URL
4. แก้ `API_URL` ใน `app.js` เป็น URL ที่ได้
5. อัปโหลด `index.html`, `app.js`, `1.jpg` (ถ้ามี) ขึ้น GitHub Pages

### ถ้าอัปเกรดจาก v2 (มีข้อมูลอยู่แล้ว)

1. วาง `Code.gs` ใหม่ทับของเดิม (Save)
2. รัน `setupSheets()` อีกครั้ง — จะสร้างชีต **Config / SchemaTypes / SchemaFields ใหม่** พร้อม seed ค่าเริ่มต้น
   (สาขา 3 สาขา, PIN ใหม่ `05032540`, login เดิม `meen`/`5340`, 5 ประเภทอุปกรณ์พร้อมฟิลด์ตามของเดิม)
   **ชีตข้อมูลอุปกรณ์เดิม (IPPhone, EDC, Pinpad, PrinterServer, PC) จะไม่ถูกแตะต้อง — ข้อมูลเดิมปลอดภัย**
3. Deploy > Manage deployments > (ไอคอนดินสอ) > Version: New version > Deploy (URL เดิมใช้ต่อได้)
4. อัปโหลด `index.html` และ `app.js` ทับของเดิม (**ต้องใช้คู่กับ Code.gs v3 เท่านั้น** ห้ามผสมกับ v2)
5. เข้าเว็บ จะเจอหน้า login ก่อน (แม้เคย login กับ v2 ไว้แล้วก็ตาม เพราะระบบ login เปลี่ยนวิธีตรวจสอบ)
   ใส่ `meen` / `5340` เข้าไปก่อน แล้วค่อยไปตั้ง PIN/password ใหม่ที่ Admin ได้

## โครงสร้างชีตทั้งหมด

| ชีต | หน้าที่ |
|---|---|
| **Config** | Key/Value — เก็บ `pin`, `loginUser`, `loginPass`, `branches` (JSON array) |
| **SchemaTypes** | `TypeKey` (รหัส, ชื่อชีตข้อมูลจริง) \| `TypeLabel` (ชื่อที่แสดงในเว็บ) |
| **SchemaFields** | `TypeKey` \| `FieldKey` (ชื่อคอลัมน์จริงในชีต) \| `FieldLabel` (ชื่อที่แสดงในฟอร์ม) \| `FieldType` (text/dropdown/date) \| `FieldOptions` (ตัวเลือก คั่นด้วย ,) \| `ShowInTable` |
| **Log** | เวลา, การกระทำ, ประเภท, ID รายการ, รายละเอียด — บันทึกอัตโนมัติทุกการเปลี่ยนแปลง รวมถึงการแก้ที่ Admin |
| **[TypeKey ต่างๆ]** เช่น IPPhone, EDC, Pinpad, PrinterServer, PC, หรือประเภทใหม่ที่เพิ่มเอง | ข้อมูลอุปกรณ์จริง — คอลัมน์เริ่มต้นเสมอด้วย `ID, สาขา, อาคาร, ชั้น, แผนก, ตำแหน่งย่อย` ตามด้วยฟิลด์เฉพาะของประเภทนั้น ปิดท้ายด้วย `สำรอง, หมายเหตุ, อัปเดตล่าสุด` |

**ห้ามแก้ชื่อคอลัมน์ในชีตอุปกรณ์ด้วยมือโดยตรง** — ถ้าจะเปลี่ยนชื่อ/เพิ่ม/ลบฟิลด์ ให้ทำผ่านหน้า Admin เท่านั้น
เพราะระบบอ้างอิงชื่อคอลัมน์ (FieldKey) ตรงๆ ในการอ่าน/เขียนข้อมูล แก้ในชีตตรงๆ จะทำให้ข้อมูลกับ Schema ไม่ตรงกัน

## หน้า Admin ทำอะไรได้บ้าง

- **สาขา** — เพิ่ม/แก้ชื่อ/ลบสาขา (ลบแล้วอุปกรณ์เดิมที่เคยผูกกับสาขานั้นจะยังมีชื่อสาขาเดิมค้างอยู่ในข้อมูล แค่ไม่มีตัวเลือกให้เลือกอีก — ไม่ได้ลบอุปกรณ์ทิ้ง)
- **ตั้งค่า PIN/Login** — เปลี่ยน PIN, user, password login ได้ทีละอย่างหรือพร้อมกัน (เว้นช่องไหนว่างไว้ = ไม่เปลี่ยนค่านั้น) ต้องกรอก PIN ปัจจุบันยืนยันเสมอ
- **Log** — ดูประวัติย้อนหลังสูงสุด 200 รายการ กรองตามช่วงวันที่และประเภทได้
- **ประเภท & ฟิลด์** — เพิ่ม/แก้ชื่อ/ลบประเภทอุปกรณ์ทั้งชีต, เพิ่ม/ลบฟิลด์ในแต่ละประเภท (เลือกชนิดฟิลด์ได้: ข้อความ/ตัวเลือก/วันที่)
  **การลบประเภทและลบฟิลด์เป็นการลบจริง ถาวร กู้คืนไม่ได้** — มีข้อความยืนยัน 2 ชั้น (confirm + PIN) ก่อนลบเสมอ

## ฟีเจอร์เดิมที่ยังอยู่ครบ

แดชบอร์ด (การ์ดสรุป + spare list), ค้นหาเบอร์แบบ real-time, จัดการอุปกรณ์ (ค้นหา/เพิ่ม/แก้/ลบ + autocomplete ตำแหน่ง),
cache ฝั่ง backend 5 นาที, โหลดข้อมูลครั้งเดียวตอนเปิดเว็บ (`action=bootstrap`) แล้วทำทุกอย่างในเครื่อง,
เก็บสำเนาไว้ใน `localStorage` เปิดได้แม้เน็ตหลุด, เวลาบันทึกเป็นเวลาไทยเสมอ

## จุดที่ควรรู้ / ทดสอบก่อนใช้จริง

- ระบบนี้ใหญ่และเปลี่ยนแกนสถาปัตยกรรมทั้งหมดจาก v2 — แนะนำให้ลองทดสอบเพิ่ม/ลบฟิลด์และประเภทใน Sheet ทดสอบก่อน ค่อยใช้กับข้อมูลจริง
- การลบฟิลด์/ประเภทเป็นการลบถาวร ไม่มีระบบ undo หรือถังขยะ ถ้าไม่มั่นใจให้สำรอง (คัดลอก) ชีตทั้งไฟล์ไว้ก่อนลองลบ
- PIN ตอนนี้เป็นเลข 8 หลัก (`05032540`) — ช่องกรอก PIN ในฟอร์มขยาย maxlength เป็น 12 แล้วรองรับ
