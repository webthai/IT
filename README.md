# IT Asset, Phone Directory & Dashboard System (v2 — แก้ปัญหาโหลดช้า)

ระบบจัดการอุปกรณ์ IT และสมุดโทรศัพท์ภายใน สำหรับทีม IT Support โรงพยาบาล (ใช้งานคนเดียว, รองรับหลายสาขา)
Frontend: HTML + CSS + Vanilla JS บน GitHub Pages · Backend: Google Apps Script + Google Sheets

ไฟล์ชุดนี้แก้ต่อจากไฟล์จริงที่ deploy อยู่ (ไม่ใช่เขียนทิ้งใหม่ทั้งหมด) — โครงสร้างข้อมูล, PIN, action เดิม, และหน้าตาเว็บยังเหมือนเดิมทุกอย่าง เปลี่ยนเฉพาะจุดที่ทำให้ช้าหรือมีบั๊ก

## สรุปทุกอย่างที่แก้ (เรียงตามผลกระทบ)

### Code.gs

| จุดที่แก้ | ของเดิมเป็นยังไง | แก้เป็นยังไง |
|---|---|---|
| **ไม่มี cache** | ทุก action อ่านชีตจาก Google Sheets ใหม่ทุกครั้ง เปิดแดชบอร์ดครั้งเดียว (`summary` + `spare`) อ่านชีต 10 รอบ | เพิ่ม `cachedRows()` เก็บผลอ่านแต่ละชีตไว้ 5 นาที ทั้งใน memory (ใช้ซ้ำภายใน request เดียว) และ `CacheService` (ใช้ข้ามคำขอ) เหลืออ่านจริง 5 รอบตอนแรกสุด แล้ว 0 รอบในคำขอถัดไปจนกว่าจะครบ 5 นาทีหรือมีการแก้ไขข้อมูล |
| **ยิงหลาย request ต่อ 1 การใช้งาน** | หน้าแดชบอร์ดยิง 2 requests, หน้าจัดการอุปกรณ์ยิง 2 requests (list + suggest), เปลี่ยนสาขา/สลับประเภทยิงใหม่ทุกครั้ง | เพิ่ม `action=bootstrap` ส่งข้อมูลทุกประเภทกลับในคำขอเดียว frontend ยิงแค่ตอนเปิดเว็บครั้งเดียว |
| **แก้ไข/ลบแล้วข้อมูลไม่อัปเดต** | ไม่มีปัญหานี้ในของเดิม (ไม่มี cache) แต่พอเพิ่ม cache เข้ามาต้องกันเรื่องนี้ | `saveRow()`/`deleteRow()` เรียก `clearCache(type)` ทันทีหลังเขียนสำเร็จ ข้อมูลใหม่มีผลทันทีไม่ต้องรอ 5 นาที |
| **เขียนข้อมูลพร้อมกันอาจชนกัน** | ไม่มี lock — ถ้ามีคนกดบันทึก 2 ครั้งพร้อมกันอาจเขียนทับกันได้ | ใส่ `LockService.getScriptLock()` ครอบ `saveRow()`/`deleteRow()` |

**ของเดิมที่ยังอยู่ครบ ไม่ได้แตะ:** `PIN_CODE`, `SPREADSHEET_ID`, `checkSetup()`, `SHEET_DEFS`, `BRANCHES`, action เดิมทุกตัว (`summary`, `spare`, `list`, `search`, `suggest`, `fieldValues`) — ยังเรียกใช้ได้ปกติ แค่เร็วขึ้นเพราะมี cache รองรับอยู่เบื้องหลัง

### index.html

| จุดที่แก้ | ของเดิมเป็นยังไง | แก้เป็นยังไง |
|---|---|---|
| **Tailwind CDN** | โหลด `cdn.tailwindcss.com` ซึ่งเป็นตัว compiler ~300KB ที่ต้องรันคอมไพล์ CSS ในเบราว์เซอร์ทุกครั้งที่เปิดหน้า | ตัดออก เขียน CSS เองใส่ใน `<style>` ในไฟล์เดียวกัน (~250 บรรทัด) หน้าตา สี (ink/teal) และ layout เหมือนเดิมทุกจุด |
| **Google Fonts** | โหลด Noto Sans Thai + IBM Plex Mono จาก `fonts.googleapis.com` (เพิ่ม network request และรอ query ฟอนต์) | ตัดออก ใช้ font-family ของระบบ (`-apple-system, Segoe UI, ...`) ซึ่งบน iOS/Windows/Android มีฟอนต์ไทยอยู่แล้ว ส่วน mono ใช้ `ui-monospace` ของระบบ |
| **ซูมหน้าจอไม่ได้** | `maximum-scale=1, user-scalable=no` ในหน้าจอมือถือ ทำให้ซูมดูตัวเลข MAC/Serial ไม่ได้ | เอาออก เหลือแค่ `width=device-width, initial-scale=1` |
| จำนวน external request รวมตอนเปิดหน้า | 3 (Tailwind + Google Fonts CSS + font ไฟล์) | 0 |

โครงสร้าง section, id ของ element, และ modal ฟอร์มเหมือนเดิมทั้งหมด — เปลี่ยนแค่ CSS classes จาก Tailwind utility เป็น class ของตัวเอง

### app.js

| จุดที่แก้ | ของเดิมเป็นยังไง | แก้เป็นยังไง |
|---|---|---|
| **ยิง API ทุกครั้งที่มีการโต้ตอบ** | เปลี่ยนสาขา → ล้าง cache แล้วยิงใหม่, สลับแท็บ → ยิงใหม่, สลับประเภทอุปกรณ์ → ยิง 2 requests | ดึงข้อมูลทั้งหมดครั้งเดียวตอนเปิดเว็บ (`loadAll`) เก็บไว้ใน `state.db` ทุกการกรอง/สลับหลังจากนั้นทำในเบราว์เซอร์ล้วนๆ ไม่ยิง server อีกเลย |
| **บั๊ก action `fieldValues`** | เรียก `apiGet({action:'fieldValues', ...})` ตอนเปิดฟอร์ม EDC เพื่อดึง Serial Number ของ Pinpad มา autocomplete — action นี้เคยไม่มีอยู่จริงในบางเวอร์ชันของ Code.gs ทำให้ช่องนี้ไม่มี suggestion | คำนวณจากข้อมูลที่มีอยู่แล้วใน `state.db` แทน ไม่ต้องยิง request เพิ่มเลย (ปัจจุบัน Code.gs รองรับ action นี้แล้วด้วย แต่ฝั่งนี้เร็วกว่าเพราะไม่ต้องรอ network) |
| **หน้าจอว่างระหว่างรอโหลด** | ทุกครั้งที่เปิดเว็บต้องรอ fetch เสร็จก่อนถึงเห็นอะไร | เก็บสำเนาไว้ใน `localStorage` เปิดเว็บครั้งถัดไปเห็นข้อมูลทันที (พร้อมบอกว่าเป็นข้อมูลที่บันทึกไว้) แล้วค่อยอัปเดตเบื้องหลังเมื่อดึงของใหม่เสร็จ — ยังเปิดดูได้แม้เน็ตหลุด |
| **ยอด "สำรอง" ไม่ตรงกับสาขาที่เลือก** | การ์ดแดชบอร์ดกรองจำนวนเครื่องตามสาขา แต่ยอดสำรองเป็นยอดรวมทุกสาขาเสมอ | คำนวณยอดสำรองจาก `rowsOf(type)` ที่กรองสาขาแล้วเหมือนกับยอดรวม ตัวเลขตรงกันแล้ว |
| **บันทึก/ลบแล้วต้องโหลดใหม่ทั้งก้อน** | เรียก `loadAssetTab()` ยิง 2 requests ใหม่ทุกครั้งหลังบันทึก | อัปเดต `state.db` ในเครื่องทันที (`applyLocal`) แล้ว sync ไปเบื้องหลัง ไม่ต้องรอ round-trip ใหม่ |
| **CORS preflight บน POST** | ของเดิมใช้ `text/plain` อยู่แล้วเพื่อเลี่ยง preflight — จุดนี้เดิมทำถูกอยู่แล้ว | คงไว้เหมือนเดิม ไม่เปลี่ยน |

`API_URL` ใส่ URL ที่ deploy อยู่ปัจจุบันไว้ให้แล้ว (`AKfycbwZ...`) — ถ้า deploy เวอร์ชันใหม่ทับของเดิมด้วย **Manage deployments > New version** ไม่ต้องแก้บรรทัดนี้อีก เพราะ URL เดิมยังใช้ได้ต่อ

## ขั้นตอนติดตั้ง / อัปเดต

### 1. อัปเดต Backend

1. เปิด Google Sheet เดิม > **Extensions > Apps Script**
2. ลบโค้ดเดิมทั้งหมด วาง `Code.gs` ไฟล์ใหม่ลงไป > Save
3. **ไม่ต้องรัน `setupSheets()` ซ้ำ** ถ้าเคยรันแล้ว (โครงสร้างชีตเหมือนเดิมทุกอย่าง)
4. **Deploy > Manage deployments > (ไอคอนดินสอ) > Version: New version > Deploy**
   ใช้วิธีนี้แทน "New deployment" เพื่อให้ URL เดิมใช้ต่อได้ ไม่ต้องแก้ `app.js`

> ทุกครั้งที่แก้ `Code.gs` ต้อง Deploy เวอร์ชันใหม่ ไม่งั้นระบบยังรันโค้ดเก่าอยู่

### 2. อัปโหลดขึ้น GitHub Pages

อัปโหลด `index.html`, `app.js` ทับไฟล์เดิมใน repo (`1.jpg` ถ้ามีไม่ต้องแตะ)

## การย้ายข้อมูลจากโครงสร้างเดิม (ถ้ายังไม่เคยทำ)

ถ้าชีตในระบบตอนนี้ยังเป็น `Printer` / `ServerPC` แยกกัน (โครงสร้างเก่าก่อนรวมเป็น `PrinterServer` + `PC`):

- ถ้าชีตเดิมยังว่าง — รัน `setupSheets()` แล้วลบชีตเก่าทิ้งได้เลย
- ถ้ามีข้อมูลอยู่แล้ว — รัน `setupSheets()` ก่อนเพื่อสร้างชีตใหม่ แล้วคัดลอกข้อมูลไปวางตามคอลัมน์ที่ตรงกันด้วยมือ (**คอลัมน์ `ID` ต้องคัดลอกไปด้วย ห้ามพิมพ์ใหม่** เพราะระบบใช้ ID อ้างอิงตอนแก้ไข/ลบ) จากนั้นค่อยลบชีตเก่า

ถ้าใช้ `PrinterServer` / `PC` อยู่แล้ว ข้ามขั้นตอนนี้ได้เลย

### ⚠️ สำคัญ: ตัดคอลัมน์ EDC และ Pinpad ให้เหลือแค่ TID / Serial Number

เวอร์ชันนี้ตัดคอลัมน์ที่ไม่ใช้ออกจาก `SHEET_DEFS`:
- **EDC**: ตัด ธนาคาร, MID, IP/SIM, Pinpad ที่เชื่อมต่อ ออก เหลือแค่ **TID**
- **Pinpad**: ตัด PC การเงินที่เชื่อมต่อ ออก เหลือแค่ **Serial Number**

**ถ้าชีต EDC / Pinpad ยังไม่มีข้อมูล** — วาง `Code.gs` ใหม่แล้วรัน `setupSheets()` ได้เลย จบ

**ถ้ามีข้อมูลอยู่แล้ว ห้ามแค่วาง `Code.gs` ใหม่แล้วรัน `setupSheets()` ทันที** เพราะ `setupSheets()` เขียนทับแค่ "ข้อความหัวตาราง" ตามตำแหน่งคอลัมน์ ไม่ได้ลบคอลัมน์เก่าออกจริง ถ้าโครงสร้างคอลัมน์ในชีตยังเป็นแบบเก่า (มี ธนาคาร/MID/IP-SIM คั่นอยู่ก่อนหน้า TID) หัวตารางจะเปลี่ยนชื่อแต่ข้อมูลข้างล่างยังอยู่ตำแหน่งเดิม ทำให้ระบบอ่านค่าธนาคารไปแสดงเป็น TID โดยไม่รู้ตัว

วิธีทำให้ปลอดภัย:
1. เปิด Google Sheet เดิม (**ยังไม่ต้องวาง Code.gs ใหม่**)
2. ไปที่ชีต **EDC** → คลิกขวาที่หัวคอลัมน์ **ธนาคาร**, **MID**, **IP/SIM**, **Pinpad ที่เชื่อมต่อ** → เลือก "ลบคอลัมน์" ทีละคอลัมน์ (เหลือไว้แค่ ID, สาขา, อาคาร, ชั้น, แผนก, ตำแหน่งย่อย, TID, สำรอง, หมายเหตุ, อัปเดตล่าสุด)
3. ไปที่ชีต **Pinpad** → ลบคอลัมน์ **PC การเงินที่เชื่อมต่อ** ออก
4. จากนั้นค่อยวาง `Code.gs` ใหม่ทับ แล้ว Deploy เวอร์ชันใหม่ตามขั้นตอนด้านล่าง (ไม่ต้องรัน `setupSheets()` ซ้ำอีก เพราะหัวตารางที่เหลืออยู่ตรงกับของใหม่แล้ว)

**อัปเดตภายหลัง: เพิ่ม Serial Number ให้ EDC และเพิ่ม TID ให้ Pinpad**

ถ้าชีต EDC / Pinpad มีข้อมูลอยู่แล้ว (ตาม TID หรือ Serial Number เดิม) **ห้ามรัน `setupSheets()` ทันทีเช่นกัน** เพราะเป็นการเพิ่มคอลัมน์ใหม่ ไม่ใช่แค่เปลี่ยนชื่อ — ถ้าเขียนหัวตารางทับตำแหน่งเดิมโดยไม่แทรกคอลัมน์จริงก่อน ข้อมูลคอลัมน์ถัดจากนั้น (สำรอง/หมายเหตุ/อัปเดตล่าสุด) จะเลื่อนไม่ตรงกับหัวตารางใหม่

วิธีทำให้ปลอดภัย:
1. เปิดชีต **EDC** → คลิกขวาที่หัวคอลัมน์ถัดจาก TID → "แทรก 1 คอลัมน์ทางซ้าย" → ตั้งชื่อหัวคอลัมน์ว่า `Serial Number`
2. เปิดชีต **Pinpad** → คลิกขวาที่หัวคอลัมน์ตำแหน่งย่อย (คอลัมน์ก่อน Serial Number เดิม) → "แทรก 1 คอลัมน์ทางขวา" → ตั้งชื่อหัวคอลัมน์ว่า `TID`
3. วาง `Code.gs` ใหม่ทับ แล้ว Deploy เวอร์ชันใหม่ (ไม่ต้องรัน `setupSheets()` เพราะหัวตารางตรงกับของใหม่แล้ว)

## สาขาและรหัส PIN

สาขา: `อโศก`, `ปิ่นเกล้า`, `อุดร` — เพิ่ม/แก้ที่ตัวแปร `BRANCHES` ทั้งใน `app.js` และ `Code.gs` ให้ตรงกัน
PIN สำหรับเพิ่ม/แก้ไข/ลบ: กำหนดที่ตัวแปร `PIN_CODE` ใน `Code.gs` (ค่าปัจจุบัน `5340`)

## โครงสร้าง Google Sheets

ทุกชีตอุปกรณ์ขึ้นต้นด้วย `ID | สาขา | อาคาร | ชั้น | แผนก | ตำแหน่งย่อย` แล้วตามด้วยคอลัมน์เฉพาะ ปิดท้ายด้วย `สำรอง | หมายเหตุ | อัปเดตล่าสุด`

| ชีต | คอลัมน์เฉพาะ |
|---|---|
| **IPPhone** | เบอร์ภายใน, IP Address, สายตรง |
| **EDC** | TID, Serial Number |
| **Pinpad** | TID, Serial Number |
| **PrinterServer** | Hostname, IP Address, MAC Address, ชื่อ Share Printer, รุ่นตลับหมึก, เลข AnyDesk |
| **PC** | Hostname, IP Address, MAC Address, สเปกเครื่อง, เลข AnyDesk |
| **Log** | เวลา, การกระทำ, ประเภท, ID รายการ, รายละเอียด |

`ID` เป็นรหัสสุ่ม 8 หลัก ห้ามแก้มือใน Sheet เพราะระบบใช้อ้างอิงตอนแก้ไข/ลบ

## ฟีเจอร์

- **แดชบอร์ด** — การ์ดสรุปจำนวนอุปกรณ์แต่ละประเภท (กรองตามสาขา) + ตารางอุปกรณ์สำรองรวมทุกประเภท
- **ค้นหาเบอร์** — พิมพ์แล้วกรองทันที ค้นจากเบอร์ภายใน สายตรง แผนก ตำแหน่ง อาคาร ชั้น
- **จัดการอุปกรณ์** — สลับประเภท, ค้นหา, กดแถวเพื่อแก้ไข, ช่องอาคาร/ชั้น/แผนก/ตำแหน่งย่อยมี autocomplete, ช่อง Pinpad ที่เชื่อมต่อดึง Serial Number จริงมาให้เลือก
- **แถบสถานะ** — บอกว่ากำลังแสดงข้อมูลสดหรือข้อมูลที่บันทึกไว้ในเครื่อง + ปุ่มดึงข้อมูลใหม่ด้วยตนเอง

## หมายเหตุ

- ยังไม่ได้ทำระบบ "สถานะอุปกรณ์" เต็มรูปแบบ (ใช้งานอยู่/ชำรุด/ส่งซ่อม) — เพิ่มภายหลังได้โดยเติมคอลัมน์ใน `SHEET_DEFS` (Code.gs) และ `ASSET_TYPES` (app.js)
- รองรับตั้งแต่จอ 320px (iPhone 6s) ถึง Desktop, ปุ่มและช่องกรอกสูงอย่างน้อย 40px กดด้วยนิ้วได้สบาย
- cache ฝั่ง backend อยู่ได้ 5 นาที (`CACHE_SECONDS` ใน `Code.gs`) — ถ้าไปแก้ข้อมูลใน Google Sheet โดยตรง (ไม่ผ่านเว็บ) เว็บจะยังเห็นข้อมูลเก่าจนครบเวลานี้ ปรับตัวเลขได้ หรือกดปุ่ม "ดึงข้อมูลใหม่" เพื่อบังคับโหลดใหม่ (cache ฝั่ง server จะยังอยู่จนครบเวลาเดิม ถ้าต้องการให้เคลียร์ทันทีให้รันฟังก์ชัน `clearAllCache()` จาก Apps Script editor)
- ถ้าข้อมูลชีตใดโตเกิน 100KB `CacheService` จะเก็บไม่ได้ ระบบจะข้าม cache ไปเองโดยไม่พัง (แค่ช้าลงเฉพาะจุดนั้น)
